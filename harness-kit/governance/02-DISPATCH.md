# 模型調度守則

## 角色與執行邊界
指揮官處理目標、風險排序、驗收、衝突仲裁及交付。大量讀取（超過三個完整檔案或 300 行）、repo 掃描、查網頁、批次改檔交代理。主模型可寫核心制度、路由、合併已審結論及必要的短工具查詢；不可藉「合併」重做代理整個工作。
每名寫作代理擁有不重疊路徑；共享檔由主模型一次整合。依賴未滿足的工作不得提早平行。總活躍代理含主模型不得超過當前工具限制，本次為 7；預設同時最多 3 個工作代理，另留驗證容量。

## 派工程序
1. 讀當前 schema 與能力快照，選最小足夠角色；在派工紀錄写「要求配置」與「實際結果」。工具接受參數不代表提供了執行模型遙測。
2. 使用模板填動機、輸入、允許修改路徑、驗收、時限/最多兩輪、回報路徑。不得只派「幫我看看」。
3. 當前使用者或適用指令已授權 override 時，首次呼叫使用 fork_turns="none" 或有限正整數並明確 model/effort；若未授權 override，省略兩參數以繼承，紀錄「繼承、未確認實際模型」，不可自行突破平台限制。fork_turns="all" 只能繼承，不可混用 overrides。
4. 寫檔代理修改前備份；回覆最多 500 字，列結論、證據 file:line、測試結果、未解、產物路徑。不要回來源全文或密鑰。
5. 完成後另派 fresh-context 驗收者；只給需求、檔案路徑、驗收條件，不给作者的「應該通過」結論。要求重新讀產物和來源。

示例（僅適用有此 schema 的平台，非 shell 命令）：
```json
{"task_name":"verify_auth","fork_turns":"none","model":"gpt-5.6-sol","reasoning_effort":"high","message":"目標：驗收認證報告。輸入：指定報告與來源絕對路徑。不得修改原始碼。核對每個結論的可達路徑與來源行號，重跑離線測試。回報：PASS/FAIL/NOT_VERIFIED、缺陷、檔案:行號、實跑命令與結果；長結果寫指定新檔。"}
```

## 升降級與重試
一次失敗＝未達已寫明驗收條件，記輸入、錯誤、命令、假設與輸出位置；不是單純不同意代理偏好。
小模型第一次實質失敗直接升中階；中階同子任務第二次實質失敗，帶兩次失敗軌跡升高階。以 task_id 累計，換代理或模型不得清零。初次執行後最多兩輪修正/驗證；若第二輪才觸發升級，升級者只診斷或提重新界定方案，不再偷偷進第三輪修改。仍不過交接為阻塞。
高階不可用：不要使用不存在 ID 重試；由可用中階拆小、加客觀測試及另一個獨立意見。涉及無法驗證的模糊判斷，請使用者或外部專家裁決，標未解。
降級條件：修復模式先在一個正例和一個邊界/反例經獨立驗收；低成本候選依固定模式批次套用，再驗收整批共同風險。不得用「一次沒報錯」直接批次推廣。

## 驗證不自驗
檔案：驗收者 read-back 完整內容、連結與交付清單。程式：至少一個行為測試或實跑，再檢查負例；編譯成功不等於功能正確。高風險：另加獨立來源意見；意見衝突依可重現證據裁定，不能投票取代證據。
沒有代理工具時：主模型可按模板循序執行最低必要工作，留下無法獨立驗收的限制；所有未獨立驗證的交付均標「待驗收」；高風險另需獨立第二意見才可完成。不必為可逆工作重問已授權事項。
